# 4. Browsing, Search, and Collections

## Search
Search should be fast enough to remain the primary way to locate sounds.

Users should be able to search by filename, file extension/type, Sample Type, Instrument/Source, Role, Genre/Style, Character, BPM, Key, duration, technical properties, user tags, and Collections.

## Faceted filters
Search results can be narrowed through visible facets such as One-shot, Loop, Phrase, Stem, Track, Drum, Bass, Vocal, Synth, BPM ranges, key/mode, Mono, and Stereo.

Filters should combine rather than replace one another.

## Results
Useful result columns may include name, Sample Type, Instrument/Source, BPM, Key, duration, format, Collection state, and suggestion/review state.

The user should be able to choose which columns are visible.

## Sorting
Results should support sorting by name, duration, BPM, key, date discovered, last used, file size, and analysis confidence.

## Collections
Collections are intentional groups of Samples.

Examples:
- Favourite Breaks
- MPC Export
- Vinyl Chops
- Field Recordings
- Drum Machine Gold

A Sample may belong to multiple Collections without creating multiple copies.

## Favourites and recents
Koffer should provide quick access to favourites, recently previewed, recently added, and recently modified/prepared Samples.

## Saved searches
A filtered query may be saved as a reusable view.

Example: One-shot + Kick + Electronic + duration under 1 second.

Saved searches remain dynamic as new matching Samples are discovered.

## Similar sounds
Where audio embeddings are available, the user may choose **Find Similar** on a Sample.

Similarity search is separate from metadata search: it asks which Samples sound related even when filenames and tags differ.
